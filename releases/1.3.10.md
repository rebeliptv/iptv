## What's New

- **Live games play again from the event page.** An event's player sat behind a greyed-out **Offline** button that did nothing when clicked — even with the game already under way and its feed working perfectly. The page had correctly worked out that the stream was playable and then handed that verdict to a player that ignored it. Channel pages were never affected.
- **Events stop dropping you into an endless "reconnecting".** When a feed genuinely isn't available, your server has always said why — the player just wasn't listening, so it retried the same dead feed fifteen times over about seventy seconds before giving up with a vague message. It now asks once, and stops straight away with the actual reason.
- **Starting a stream no longer competes with the hourly refresh.** Pressing play kicks off a quick lookup before the picture starts, and that lookup was queued behind the refresh's own web requests. While a refresh was running it could time out and hand you a "temporarily unavailable" screen for a feed that was completely healthy.
- **NFL games get a proper event page.** American football was falling back to the generic layout it shares with every unstyled sport. It now has its own: team comparison and records on one side, quarterbacks, leaders, recent form and injuries on the other — and, once a game is under way, a drive strip across the top showing who has the ball, the down and distance, field position, timeouts and the last play.
- **One slow source address no longer knocks out a whole provider.** Where a provider publishes several addresses, your server tries each in turn — but they were all sharing a single stopwatch, so if the first was slow it ran the clock out and the rest were abandoned untried. A provider with a perfectly good backup address went dark for the hour. Each address now gets its own time to answer.

## Update

Already running Rebel IPTV? Update to this version — your data (the `iptv-data` volume) is kept. From the dashboard, click **Update now** on the Dashboard or in **Settings → Server** (on the `:latest` image with the Docker socket mounted). Or from the command line:

```bash
docker pull rebeliptv/iptv:1.3.10
docker compose up -d
```

Setting up a **new** instance? The step-by-step guide at **https://www.rebeliptv.com** builds a Docker configuration for your system — ports, timezone, in-app updates, and more — so you copy a setup that fits your box instead of a generic one.

Image: `rebeliptv/iptv:1.3.10` (also published as `rebeliptv/iptv:latest`).

## Endpoints

| URL | Description |
|-----|-------------|
| `http://<server>:8080/playlist?key=YOUR_KEY` | M3U playlist |
| `http://<server>:8080/epg?key=YOUR_KEY` | EPG guide (XML) |
| `http://<server>:8080/epg.gz?key=YOUR_KEY` | EPG guide (gzip) |
| `http://<server>:8080` | Web dashboard |

> **Note:** The `?key=` parameter is only required if an API key has been generated in the web dashboard under **Settings**.
