## What's New

- **The guide now tells you what a programme is about.** Hovering a cell used to repeat the title and the time and nothing more. It now opens a card with the synopsis — "The TCU Horned Frogs and North Carolina Tar Heels clash at Aviva Stadium in Dublin for the Aer Lingus Classic…" — so you can tell one slot from another without opening anything. The guide loads exactly as fast as before: descriptions are fetched for a channel the first time you point at its row, not bundled into the page. (Thanks to @smith288 for the suggestion, including the one about fetching on hover.)
- **Live football games now show the drive.** For a game in progress the page adds the down and distance, which team has the ball and where, whether they are in the red zone, and each side's remaining timeouts — the strip was built and styled but had never appeared, because the data never reached the page. It does now.
- **The Sports page now says so when listings stop updating.** Games are identified using outside schedule services, and when one can't be reached the sports section quietly stopped filling — with nothing to explain it, since the dashboard still read "Healthy". A dismissible banner now names the leagues that have stopped updating, the ones still working, and how long it has been going on. If the service is refusing us it also says what is usually behind that: **some VPN and hosting providers are blocked from it**, so an instance behind one may need a different exit or a direct connection.
- **Weather on a game now reads as words.** The temperature was followed by a bare number — "80°F · 38" — because the listings service labels its two weather fields the opposite way round to what they contain. It reads "80°F · Partly cloudy".
- **Channels that should play now play.** Several separate faults had the same effect — a channel that worked in VLC returning nothing here. Some providers only serve players and turn away anything that looks like a web browser, which is how your instance was identifying itself. Some serve their channel list from one machine and the video from another, and the second address was forgotten every time the instance restarted, so a provider that worked yesterday failed after an update until the next refresh, up to an hour later. And a source that simply started slowly could be set aside for five minutes as though it were dead, on every channel it appeared on. All three are fixed.
- **Channels are no longer shown as offline while they are playing perfectly.** Your instance checks whether a channel is alive by asking its provider a short "are you there" question, and some providers do not answer that question at all even though they serve the video itself without complaint. Every channel from such a provider was marked offline on the dashboard and skipped as a fallback while it was streaming fine. The check now asks for the video before deciding. A provider that really is down is still marked down.
- **The TV guide no longer goes blank.** Two things could empty it. The guide is downloaded at the very end of a refresh, so a restart, an update or a crash part-way through left every channel working and the guide completely empty — and on the next start-up your instance saw it had channels, decided all was well, and waited up to an hour before filling it in. Separately, the guide is assembled from several large files, and one being cut off part-way through made your instance throw the whole download away and start over, three times, before giving up for that cycle. It now notices an empty guide at start-up and fetches it straight away, and a cut-off download picks up where it stopped instead of starting again. This was the most common fault across every instance we see.
- **A provider's channels no longer come and go between refreshes.** Two channel lists were large enough that downloading them took longer than the time allowed, so they failed on most refreshes and their channels slowly stopped being offered — even though the same provider played perfectly in VLC. Downloads are now judged on whether they are still making progress rather than on finishing inside a fixed window, and one list now arrives compressed, which is the same data in a twelfth of the bytes. One provider that had been failing two refreshes in three now brings in over four hundred channels.
- **A live game you can already watch no longer goes missing because a schedule lookup failed.** When your instance takes its streams from Rebel, a game with a working stream now reaches the playlist and the guide on the strength of that stream alone — the matchup and the start time are there, and only the extras that come from the schedule service are not: scores, records, team colours, venue. Until now the whole game was thrown away instead, so a bad afternoon for that service, or a competition it does not cover, emptied the sports section of an instance whose streams were all perfectly fine.
- **Switching between local scraping and Rebel's feeds now actually takes.** Flipping the source mode wiped the events and rebuilt them, and then the old ones reappeared — leaving the instance looking like it had never switched, with no way to clear it but "Purge & Rescrape", repeatedly, until it happened to stick. A background job that re-checks event streams could take a minute to finish its round, and if the switch landed mid-round it wrote everything it had been holding back over the top of the new data. It now notices the ground moved under it and drops that round instead.

## Update

Already running Rebel IPTV? Update to this version — your data (the `iptv-data` volume) is kept. From the dashboard, click **Update now** on the Dashboard or in **Settings → Server** (on the `:latest` image with the Docker socket mounted). Or from the command line:

```bash
docker pull rebeliptv/iptv:1.4.4
docker compose up -d
```

Setting up a **new** instance? The step-by-step guide at **https://www.rebeliptv.com** builds a Docker configuration for your system — ports, timezone, in-app updates, and more — so you copy a setup that fits your box instead of a generic one.

Image: `rebeliptv/iptv:1.4.4` (also published as `rebeliptv/iptv:latest`).

## Endpoints

| URL | Description |
|-----|-------------|
| `http://<server>:8080/playlist?key=YOUR_KEY` | M3U playlist |
| `http://<server>:8080/epg?key=YOUR_KEY` | EPG guide (XML) |
| `http://<server>:8080/epg.gz?key=YOUR_KEY` | EPG guide (gzip) |
| `http://<server>:8080` | Web dashboard |

> **Note:** The `?key=` parameter is only required if an API key has been generated in the web dashboard under **Settings**.
