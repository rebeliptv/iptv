## What's New

- **A second way to connect: your server can now be added to Plex, Emby and Channels DVR as a tuner.** Those apps build their Live TV around HDHomeRun network tuners — an M3U playlist has always been the awkward path there, when it worked at all — so your server can now answer as one. In Plex, open *Live TV & DVR*, click **Don't see your HDHomeRun?**, and give it the address shown in **Settings → Connect → HDHomeRun tuner**; point the guide at your **EPG Guide** URL and you have live TV with a proper channel grid, DVR and pause/rewind. Emby and Channels DVR are the same story, and Jellyfin can use either this or the M3U Tuner. The Playlist URL is unchanged and keeps working exactly as before. The same page lets you set how many channels can be watched at once, or turn the tuner off entirely. Note your server does **not** announce itself on your network — you always add it by address, the same way you paste the Playlist URL.
- **Your channel numbers now travel with the guide.** The guide file now lists each channel's number as well as its name. Some players match the guide to your channels by number instead of by name — this is how Plex, Emby and Channels DVR do it when you connect your server as a tuner — so your listings now line up with your channels on their own, rather than leaving them showing "No guide info".
- **New `HEADLESS=true` option for boxes with no browser.** If your server runs somewhere you never open the dashboard — a Kodi or LibreELEC box, a NAS, a machine you only reach over SSH — set `HEADLESS: "true"` in your compose file. The update prompt has always been part of the dashboard, so an instance nobody visits was never told a new version existed and quietly fell behind until it stopped working. In headless mode the server checks for itself and installs new versions on its own, waiting for a moment when nothing is streaming so it never cuts off a viewer, and it skips the first-run setup screen so a fresh install starts building your playlist without a single visit to the dashboard. It needs the `/var/run/docker.sock` mount and the `:latest` tag — the same two things the **Update now** button needs — and logs how to update by hand if either is missing.
- **A server that's too out of date to run now says so in your browser, instead of only in its log.** Previously a server in that state didn't answer at all — you'd open the dashboard and get a connection error, with the actual explanation buried in `docker logs` where most people would never see it. Now it serves a page on its usual address telling you what's wrong, with an **Update now** button right there when one-click updates are available, and it tells you what happens if you do nothing: left alone for half an hour it updates itself rather than sit there dead, since a server in this state isn't serving anything anyway.
- **If your setup can't update itself, that page now tells you how to change that.** A server with no Docker socket mapped can't be rescued automatically, which is how it ends up stuck in the first place — so instead of only listing commands to run, the page gives you the exact line to add to your compose file, ready to copy, and explains that with it in place the server will handle this by itself next time rather than stop working. Same for a server pinned to a fixed version tag.
- **The "please update" message now tells you the right command.** `docker restart` looks like it should apply an image you just pulled, but it starts the same container on the same old image — so the server comes back still out of date and the update looks broken. The message now says to use `docker compose pull && docker compose up -d`, and says plainly why restarting isn't enough.
- **Your TV guide no longer comes up empty on a slower connection.** Guide listings arrive as a few large compressed files, and each download used to be given a flat thirty seconds to finish, however big it was. On a fast connection you'd never notice. On a slower one the biggest files simply ran out of time before they were done, so the channels they cover showed no listings at all — every refresh, with nothing on screen to explain why. Downloads now take as long as they need, and are only given up on if they genuinely stall.
- **Fewer channels dropping out while you're watching them.** Now and then a channel's feed turns down a request for a moment, even though it is otherwise streaming perfectly. Your server used to take that as the feed having died and switch you straight over to a backup one, which you'd see as the picture stuttering, reloading, or losing its sound. It now simply asks again a few times, and only switches if the feed really has stopped answering — so a brief hiccup no longer costs you the channel.
- **A custom source's username and password can no longer appear in diagnostic reports.** If you added a custom source whose address carries a login in it — the usual form for an Xtream panel — then a failure to reach that source could include the full address, credentials and all, in the diagnostics your server reports back about errors. Those values are now masked before anything is sent.
- **If your server's database gets damaged, it now says so — and says that a restart fixes it.** A machine that runs out of memory can leave the working copy of the database broken. When that happened, your channel list and TV guide quietly stopped updating while everything else carried on looking normal, and the only sign of it was a line in the log that didn't say what to do. Your server now states it plainly and names the fix: restart the container, and on start-up a damaged database is thrown away and rebuilt from the last good copy. A server that's simply short on memory now says that too, instead of failing its regular backup with an error nobody could read.
- **If the port your server needs is already taken, the log now tells you how to get going again.** All it used to print was the raw error — `bind: address already in use` — after which the container restarted into the same wall over and over, indefinitely. It now explains the usual cause (an older copy of this container still running, or another app on that port) and gives you the two ways out: stop whatever is holding the port, or set `PORT` to a free one and publish that instead.

## Update

Already running Rebel IPTV? Update to this version — your data (the `iptv-data` volume) is kept. From the dashboard, click **Update now** on the Dashboard or in **Settings → Server** (on the `:latest` image with the Docker socket mounted). Or from the command line:

```bash
docker pull rebeliptv/iptv:1.3.7
docker compose up -d
```

Setting up a **new** instance? The step-by-step guide at **https://www.rebeliptv.com** builds a Docker configuration for your system — ports, timezone, in-app updates, and more — so you copy a setup that fits your box instead of a generic one.

Image: `rebeliptv/iptv:1.3.7` (also published as `rebeliptv/iptv:latest`).

## Endpoints

| URL | Description |
|-----|-------------|
| `http://<server>:8080/playlist?key=YOUR_KEY` | M3U playlist |
| `http://<server>:8080/epg?key=YOUR_KEY` | EPG guide (XML) |
| `http://<server>:8080/epg.gz?key=YOUR_KEY` | EPG guide (gzip) |
| `http://<server>:8080` | Web dashboard |

> **Note:** The `?key=` parameter is only required if an API key has been generated in the web dashboard under **Settings**.
